# hot-seat 2–4 คน ใน Godot — เอกสารออกแบบ

วันที่: 2026-08-22 · งานนี้ปิดช่องว่างสุดท้ายระหว่างต้นแบบเว็บกับพอร์ต Godot

## ทำไมต้องมีเอกสารนี้

GDD บทที่ 10 ติ๊ก ✅ ให้ **MULTIPLAYER (hot-seat)** ว่า "เสร็จแล้ว" — แต่ที่เสร็จคือ
`ui.html` ต้นแบบเว็บ ส่วน Godot ยังเล่นได้คนเดียวเสมอ (`ui/main.gd:122` ฮาร์ดโค้ด
`mode: "solo"` + คนจริง 1 + บอท 2 ตัวชื่อตายตัว) ใครอ่าน GDD อย่างเดียวจะเข้าใจผิดว่า
ฟีเจอร์นี้มีอยู่ในเกมจริงแล้ว

งานนี้ไม่ใช่การ "พอร์ตระบบใหม่" — **core รองรับอยู่แล้วครบทุกข้อ** สิ่งที่ขาดคือชั้นบนสุด
ที่ไม่เคยเปิดทางให้มีคนจริงมากกว่าหนึ่งคนเดินเข้ามา

## ข้อเท็จจริงที่ตรวจกับโค้ดจริงแล้ว (ไม่ใช่การคาดเดา)

ตรวจก่อนออกแบบ เพราะถ้า core ไม่รองรับ ขนาดงานจะต่างกันคนละเรื่อง:

- `core/match.gd:79` `run_ai_turns()` หยุดรอ **ทุกคน** ที่ `is_ai == false` ไม่ใช่แค่คนแรก
  — ลูปเดินบอทจนเจอคนจริงคนถัดไปแล้ว `return` ออกไปรอ
- `core/match.gd:258` `start_index = (start_index + 1) % players.size()` ทุกสิ้นเดือน
  — **ลำดับตาหมุนรายเดือนพอร์ตมาแล้ว** ตรงกับ `engine.js:1223`
- `core/match.gd:247` เงื่อนไขจบเกมนับ "คนจริงทุกคน" อยู่แล้ว บอทชนะไม่ทำให้เกมจบ
- `core/save.gd:31` เก็บ `is_ai` รายคน และ `save.gd:55` เก็บ `mode` / `start_index` / `turn`
  — **ฟอร์แมตเซฟรองรับ hot-seat อยู่แล้ว ไม่ต้องขึ้น `VERSION` ใหม่**
- `ui/main.gd:342` `_refresh()` bind วิดเจ็ตทั้ง 16 ตัวกับ `m.get_current()`
  — **จอเปลี่ยนตามคนที่ถึงตาเองอยู่แล้ว** ไม่ต้องแก้วิดเจ็ตสักตัว
- `data/jobs.json` มี 16 อาชีพ ทุกตัวมีช่อง `tier` (1–4) ใช้ตัดสินโบนัสชั่วโมงของบอทได้
- ฝั่งที่ยังไม่รองรับ: `ui/main.gd:122` (ผู้เล่นตายตัว) · `ui/screens/setup_screen.gd`
  (ทอยเต๋าได้รอบเดียว) · ไม่มีหน้าเมนู · ไม่มีม่านส่งเครื่อง ·
  `ui/main.gd:171` ล็อกเสียงไว้กับคนจริง**คนแรก**ตลอดเกม

## สี่ข้อที่เจ้าของโปรเจกต์ตัดสินแล้ว

1. **เข้าทางหน้าเมนูใหม่** ที่มาก่อนหน้าทอยเต๋า ไม่ใช่ปุ่มแทรกบนหน้าทอยเต๋า
2. **เติมบอทให้ครบ 4 ที่นั่งเสมอ** ตามต้นแบบ — solo กลายเป็น คุณ + บอท 3
   (เดิม Godot มีบอท 2 ตัว) · 4 คนจริง = ไม่มีบอท
3. **ม่านส่งเครื่องมีแค่ม่านทึบกับปุ่ม** ไม่มีนาฬิกาจับเวลา ไม่มีสรุปตาที่แล้ว
4. งานนี้ไม่แตะ `core/player.gd` `core/match.gd` `core/ai.gd` `core/rng.gd`
   — **ผลต้องยังตรงกับ `engine.js` 960/960 หลังทำเสร็จ**

## สถาปัตยกรรม

```
เปิดเกม
  └─ WQModeSelect  (ใหม่)  ── เล่นคนเดียว / 2 / 3 / 4 คน / โหลดเกม
        └─ WQSetupScreen  ×N  ── ทอยเต๋า → เลือกอาชีพ  (คนละเมล็ดสุ่ม)
              └─ WQSetup.fill_bots()  ── เติมบอทจนครบ 4 ที่นั่ง
                    └─ WQMatch.setup()  ── ของเดิม ไม่แก้
                          └─ WQPassScreen  (ใหม่)  ── ม่านก่อนตาของคนจริงทุกคน
```

หน่วยงานแต่ละตัวมีหน้าที่เดียว:

| หน่วย | ทำอะไร | ขึ้นกับอะไร |
|---|---|---|
| `WQModeSelect` | ถามว่าเล่นกี่คน ยิง `chosen(human_count)` | ไม่ขึ้นกับแมตช์ — ยังไม่มีแมตช์ตอนนั้น |
| `WQSetupScreen` | ทอยเต๋า + เลือกอาชีพของ **ที่นั่งเดียว** | `WQSetup.roll_start()` เท่านั้น |
| `WQSetup.fill_bots()` | คืนรายการที่นั่ง **ทั้งโต๊ะ** (คนจริง + บอทที่เติมจนครบ 4) | `WQData.jobs` + `WQRng` ที่ส่งเข้ามา |
| `WQPassScreen` | ปิดจอจนกว่าคนที่ถึงตาจะกดพร้อม | ชื่อ + อาชีพของผู้เล่นหนึ่งคน |
| `ui/main.gd` | ร้อยลำดับทั้งหมด เก็บ `_seats` | ทุกตัวข้างบน |

## รายละเอียดแต่ละส่วน

### 1. `ui/screens/mode_select.gd` — `WQModeSelect`

หน้าจอเต็มจอ พื้น `WQPalette.BG_DEEP` · ปุ่มห้าปุ่ม: เล่นคนเดียว · 2 คน · 3 คน · 4 คน ·
โหลดเกม · สัญญาณ `chosen(human_count: int)` และ `load_requested`

ใต้ปุ่มแต่ละอันบอกให้ชัดว่าที่นั่งที่เหลือเป็นบอท ("คุณ + บอท 3 ตัว") เพราะจำนวนคู่แข่ง
ในตลาดดีลมีผลต่อเกมจริง — `refill_market()` ตั้งเป้าจำนวนดีลจาก `4 + players.size()`

`WQ_HUMANS=<1-4>` ข้ามหน้านี้ไปเลย (สำหรับถ่ายภาพหน้าจอและเทสต์)
`WQ_JOB=<job_id>` ยังทำงานเหมือนเดิม = เริ่ม solo ทันทีโดยไม่ผ่านทั้งเมนูและหน้าทอยเต๋า

### 2. `WQSetupScreen` วนทีละที่นั่ง

`main.gd` ถือ `_seats: Array[Dictionary]` และ `_seat_idx: int`

- `start(seed, seat_label := "")` — พารามิเตอร์ใหม่ `seat_label` ใช้ขึ้นหัวข้อ
  "ผู้เล่น 2 — ทอยเต๋าเปิดโอกาสของคุณ" · ว่างไว้ = solo = หัวข้อเดิมไม่เปลี่ยน
- **เมล็ดสุ่มต่อที่นั่ง = `SEED + seat_idx * 7919`** สูตรเดียวกับ `ui.html:381`
  ถ้าใช้เมล็ดเดียวกันทุกคน ทุกคนจะทอยได้แต้มเดียวกันและได้ชุดอาชีพเดียวกันเป๊ะ
- เลือกอาชีพเสร็จ → เก็บที่นั่งลง `_seats` → ยังไม่ครบก็ปิดหน้าเดิมแล้วสร้างหน้าใหม่
  สำหรับที่นั่งถัดไป (ปิดด้วย `_close_screen()` ตัวเดิมที่ `free()` แบบ deferred —
  กฎเดิมของโปรเจกต์: ห้าม `free()` หน้าจอทิ้งระหว่างปุ่มของมันกำลังส่งสัญญาณ)
- **อาชีพซ้ำกันได้** ต้นแบบไม่ห้ามคนจริงเลือกซ้ำ (`ui.html:419` ไม่กรองอะไรเลย)
  ที่กรองคือฝั่งบอทเท่านั้น

### 3. `WQSetup.fill_bots()` — อยู่ใน core ไม่ใช่ UI

การเติมที่นั่งเป็น **กติกาของแมตช์** ไม่ใช่เรื่องหน้าจอ จึงอยู่ที่ `core/setup.gd`
เหมือน `roll_start()` และ `job_preview()`

```gdscript
const BOT_NAMES := ["พี่เอ๋ (บอท)", "เจ๊หมวย (บอท)", "น้องบีม (บอท)", "ลุงวิรัช (บอท)"]

## รับที่นั่งของคนจริงเข้ามา คืนที่นั่ง **ทั้งโต๊ะ** ที่พร้อมส่งให้ `WQMatch.setup()`
static func fill_bots(seats: Array, rng: WQRng) -> Array
```

- สุ่มอาชีพจากตัวที่ **ยังไม่มีใครในโต๊ะใช้** (ตรงกับ `ui.html:421`)
- `bonus_hours = 20` ถ้า `tier <= 1` มิฉะนั้น 0
- ชื่อไล่จาก `BOT_NAMES` ตามลำดับ
- เติมจนโต๊ะมี 4 ที่นั่ง หรือจนอาชีพหมด (16 อาชีพ ไม่มีทางหมดจริง แต่กันไว้)

**กฎเหล็กของงานนี้: ห้ามใช้ `m.rng`** ตัวสุ่มของแมตช์เป็นของที่ต้องเดินตรงกับ `engine.js`
ทีละครั้ง ถ้าดึงเลขจากมันไปเลือกอาชีพบอท ผลทั้ง 960 เกมจะเลื่อนหมด
`main.gd` จะสร้าง `WQRng.new(SEED + 555)` ขึ้นมาใช้แล้วทิ้งทันที

### 4. `ui/screens/pass_screen.gd` — `WQPassScreen`

ม่านทึบเต็มจอ (`ColorRect` สี `BG_DEEP` ทึบ 100% — ต้องทึบจริง ไม่ใช่โปร่งแสง
เพราะหน้าที่เดียวของมันคือไม่ให้คนอื่นเห็นจอของคนที่ถึงตา) · ไอคอนอาชีพขนาดใหญ่ ·
"ตาของ &lt;ชื่อ&gt;" สีทอง · บรรทัดรอง "ส่งเครื่องให้ผู้เล่นคนนี้ แล้วกดปุ่มเพื่อเริ่มตา" ·
ปุ่มเดียว "พร้อมแล้ว เริ่มตาของฉัน" · สัญญาณ `ready_pressed`

**เงื่อนไขที่ม่านต้องโผล่:** มีคนจริงมากกว่า 1 คนในโต๊ะ **และ** คนที่ถึงตาเป็นคนจริง
**และ** ยังไม่ได้กดผ่านสำหรับตานี้ · solo ไม่มีม่านเลย

**จุดยิง:** หลัง `_end_turn()` (ซึ่งเรียก `m.end_turn()` แล้วบอทเดินเองจนถึงคนจริงคนถัดไป)
และหลังโหลดไฟล์เซฟ

**ต้องเพิ่ม `pass_screen != null` ในเงื่อนไขของ `_unhandled_input`** (`ui/main.gd:510`)
ไม่งั้นเคาะ SPACE ทะลุม่านไปจบตาของคนที่ยังไม่ได้เริ่มเล่นได้

**จุดเดียวที่ทำต่างจากต้นแบบโดยตั้งใจ:** `ui.html:437` เช็ค `pendingDream` **ก่อน** ม่าน
แปลว่าการ์ดความฝันของคุณเด้งใส่หน้าคนที่เพิ่งส่งเครื่องมาให้ ที่นี่ **ม่านมาก่อนเสมอ**
แล้วค่อยเปิดหน้าทอยความฝันหลังกดพร้อม

### 5. เสียงตามคนที่ถึงตา

`ui/main.gd:171` วนหาคนจริง**คนแรก**แล้ว `WQAudio.bind_player()` ครั้งเดียวตอน adopt
ในเกม hot-seat เสียงของผู้เล่นคนที่ 2–4 จะเงียบสนิท และเพลงวิกฤตจะอ่านสุขภาพของคนแรก
ตลอดเกม

แก้เป็น bind ใน `_refresh()` ตามคนที่ถึงตา (ข้ามเมื่อเป็นบอท เพื่อไม่ให้เสียงของบอทดัง —
กฎเดิมที่ `main.gd` ใช้อยู่หลายจุด) · `bind_player()` คืนทันทีถ้าเป็นคนเดิม (`audio.gd:131`)
จึงเรียกทุก `_refresh()` ได้ไม่มีผลข้างเคียง

### 6. การสอนเปิดเฉพาะ solo

`tutorial.bind()` ผูกกับผู้เล่นคนเดียวตอน `_adopt_match` และการ์ดชี้ไปที่วิดเจ็ตของคนนั้น
ในเกมหลายคนมันจะชี้ผิดคนทันทีที่เปลี่ยนตา · hot-seat จึงข้าม `tutorial.start()` ไปเลย

### 7. เซฟ/โหลด

ฟอร์แมตไม่เปลี่ยน `VERSION` คงที่ 6 · แก้จุดเดียวคือ `meta_of()` (`core/save.gd:63`)
ซึ่งหยิบคนจริง**คนแรก**มาโชว์เป็นหัวไฟล์ — เพิ่มช่อง `humans` (จำนวนคนจริง) ให้หน้ารายการเซฟ
แสดง "hot-seat 3 คน" ได้ ไม่งั้นเซฟของเกม 3 คนกับ solo หน้าตาเหมือนกันจนแยกไม่ออก

โหลดเสร็จแล้วถ้าเป็นตาคนจริงในเกมที่มีคนจริงหลายคน → เปิดม่านทันที (คนโหลดอาจไม่ใช่
คนที่ถึงตา)

### 8. เทสต์

hot-seat จะตั้ง `WQ_HUMANS` เองในเทสต์

## สิ่งที่ **ไม่** ทำในงานนี้ (YAGNI)

- ตั้งชื่อผู้เล่นเอง — ใช้ "ผู้เล่น 1..4" ตามต้นแบบ
- นาฬิกาจับตา / auto-pass — เจ้าของโปรเจกต์ตัดออกแล้ว
- หน้าสรุปตอนจบแมตช์ — เป็นงานแยก (ตอนนี้แบนเนอร์ประกาศแชมป์อยู่)
- เลือกจำนวนบอทเอง — เติมครบ 4 เสมอ
- online multiplayer — GDD บทที่ 15 ห้ามเริ่มก่อนถามเจ้าของโปรเจกต์

## เกณฑ์ว่างานนี้เสร็จ

1. เปิดเกม เลือก "2 คน" ทอยเต๋าและเลือกอาชีพได้สองรอบ แล้วเข้าเกมที่มีคนจริง 2 + บอท 2
2. จบตาคนแรกแล้ว **เห็นม่านจริง** ก่อนจอของคนที่สอง (ยืนยันด้วยภาพหน้าจอ ไม่ใช่แค่เทสต์)
3. เล่นข้ามเดือนแล้วลำดับตาหมุน — คนที่สองได้เริ่มก่อนในเดือนถัดไป
4. เซฟระหว่างเกม 2 คน โหลดกลับมาแล้วอยู่ที่ตาเดิม คนเดิม พร้อมม่าน
5. สูททั้ง 8 ตัวเขียว และ `parity_dump` ยังตรง `engine.js` 960/960
6. `godot/README.md` กับ `godot/CLAUDE.md` อัปเดตสถานะ hot-seat แล้ว
