## โปรเจกต์นี้คืออะไร

**Wealth Quest** — เกมการเงิน 2.5D สำหรับ PC/Steam ทำโดยนักพัฒนาคนเดียว
ผู้เล่นสวมบทอาชีพจริงในไทย แล้วต้องสร้างรายได้จากทรัพย์สินให้มากกว่ารายจ่าย
โดยบริหารทรัพยากรสามอย่างที่ขัดแย้งกัน: **เงิน · เวลา (720 ชม./เดือน) · สุขภาพ**

เอกสารออกแบบฉบับเต็มอยู่ที่ `../WEALTH-QUEST-GDD.md` — **อ่านบทที่ 3, 4, 13 ก่อนเริ่ม**

## สถานะปัจจุบัน

- ✅ ต้นแบบเว็บ (`../wealth-quest-prototype.html`) เล่นจบได้จริง สมดุลผ่านการจำลอง 4,000+ เกม
- ✅ พอร์ต core มาเป็น GDScript ในโฟลเดอร์นี้แล้ว **แต่ยังไม่เคยรัน** (เขียนในสภาพแวดล้อมที่ไม่มี Godot)
- ⬜ UI ยังเป็นแค่ RichTextLabel ตัวเดียว
- ⬜ ยังไม่มีงานอาร์ต เสียง หรือฉาก 2.5D

## 🔴 งานแรกที่ต้องทำ — ตรวจว่าพอร์ตถูกต้อง

```bash
godot --headless --script res://sim/headless_sim.gd
```

1. แก้ syntax error จนรันผ่าน (คาดว่ามีบ้าง เพราะยังไม่เคยคอมไพล์)
2. เทียบผลกับตารางอ้างอิงด้านล่าง — **ตัวเลขต้องใกล้เคียงกัน** ถ้าต่างเกิน ±15% แปลว่าพอร์ตผิดตรงไหนสักแห่ง
3. จุดที่พอร์ตพลาดง่ายที่สุดคือ `core/rng.gd` — `Math.imul` ของ JS เป็นการคูณ 32-bit
   ถ้าตัวสุ่มไม่ตรง ทุกอย่างจะเพี้ยนหมด **ทดสอบตัวสุ่มก่อนเป็นอันดับแรก**

## ⚠️ ระบบที่เพิ่มเข้ามาหลังพอร์ตรอบแรก — ยังไม่มีใน GDScript

ต้นแบบเว็บ (`../wealth-quest-prototype.html`) มี **ระบบแผนที่และการเดินทาง** แล้ว แต่ GDScript ในโฟลเดอร์นี้ยังไม่มี
ข้อมูลอยู่ใน `data/places.json` เรียบร้อยแล้ว — ต้องพอร์ตเพิ่ม (ดูบทที่ 3A ของ GDD):

- `player.place` + `travel_to(place_id)` — เวลา = `max(1, round(|xA-xB| × travel_rate × ตัวคูณพาหนะ))`
- `place_for(act)` / `can_do_here(act)` — ทุกการกระทำผูกกับสถานที่ และอุปกรณ์เป็นทางลัด
- `buy_vehicle()` / `buy_device()` — พาหนะลด `commute` ด้วย ไม่ใช่แค่เวลาเดินทาง
- แพ็กเกจฟิตเนส/รีสอร์ต (`exercise(pack_id)` / `vacation(pack_id)`)
- AI ต้องวางแผนเส้นทาง: คะแนน = ผลตอบแทน ÷ (เวลาทำ + เวลาเดินทาง)
- สิ้นเดือน: `place = "home"`, `travel_used = 0`, `gym_pack = null`, `shield = 0`

**ให้ `../engine.js` เป็น reference เสมอ** — มันคือฉบับที่ผ่านการจำลองแล้ว

## กฎเหล็กของโปรเจกต์

1. **`core/` ห้ามรู้จัก UI เลย** — ห้าม `preload` อะไรจาก `ui/` หรือ `world/` ห้ามเรียก `get_node`
   นี่คือสิ่งเดียวที่ทำให้รันจำลอง 4,000 เกมได้ในไม่กี่วินาที ถ้าพังข้อนี้ จะปรับสมดุลไม่ได้อีกเลย
2. **ตัวเลขสมดุลอยู่ใน `data/*.json` เท่านั้น** ห้าม hardcode ตัวเลขในโค้ด
3. **แก้ตัวเลขเมื่อไหร่ ต้องรัน headless sim ทุกครั้ง** ก่อน commit
4. **state ของตัวสุ่มต้องอยู่ในไฟล์เซฟเสมอ** ไม่งั้นผู้เล่น save-scum ได้
5. UI ต้อง subscribe สัญญาณ (`month_ended`, `changed`, `disaster_started`) **อย่า redraw ทั้งหน้าจอทุกเฟรม**

## โครงไฟล์

```
core/       ตรรกะบริสุทธิ์ — rng, game_data, player, match, ai, save
data/       ตารางสมดุลทั้งหมดเป็น JSON (สร้างจาก engine.js เดิม)
sim/        headless simulation
ui/         หน้าจอและ widget (ยังเป็น placeholder)
world/      ฉาก 2.5D (ยังว่าง)
```

## ลำดับงานที่แนะนำ

1. **ตรวจพอร์ต** — รัน sim ให้ผ่าน (ข้างบน)
2. **UI หลัก** ตามเลย์เอาต์ในบทที่ 12 ของ GDD — เรียงตามความสำคัญ:
   `widgets/time_budget` → `widgets/deal_card` → `widgets/statement` → `widgets/health_bar` → `widgets/standings`
3. **หน้าจอ setup** — ทอยเต๋า → เลือกอาชีพ (บทที่ 7 ของ GDD)
4. **ด่าน 2** — ทอยเต๋าสุ่มความฝัน + เลือกลาออก/ทำงานต่อ (บทที่ 9)
5. **บันทึก/โหลด + autosave 3 ช่อง** (`core/save.gd` พร้อมแล้ว ต่อ UI อย่างเดียว)
6. **tutorial 5 เดือนแรก** — ลอกสเต็ปจากต้นแบบเว็บได้เลย (ตัวแปร `TUT` ใน `../ui.html`)
7. ฉาก 2.5D และงานอาร์ต — **ทำท้ายสุด** ดูเหตุผลในบทที่ 12.3

## สิ่งที่ห้ามทำโดยไม่ถามเจ้าของโปรเจกต์ก่อน

- เปลี่ยนตัวเลขสมดุลใน `data/` (มีผลต่อทั้งเกม ต้องรัน sim ยืนยันเสมอ)
- เริ่มทำ online multiplayer (ดูบทที่ 15 — ต้องรอ core loop นิ่งก่อน)
- เพิ่ม dependency ภายนอก
- ใช้ชื่อ "Cashflow" หรือทรัพย์สินทางปัญญาของ Ragnarok Online ที่ไหนก็ตาม (บทที่ 18)
