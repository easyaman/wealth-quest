## 0. เกมนี้คืออะไร (บริบทที่ AI ต้องรู้ก่อนผลิตงาน)

เกมการเงินแนว management/roguelite ฉากประเทศไทย ผู้เล่นสวมบทอาชีพจริง (16 อาชีพ)
แล้วบริหารทรัพยากรสามอย่างที่ขัดแย้งกันเอง: **เงิน · เวลา (720 ชม./เดือน) · สุขภาพ**
เป้าหมายคือทำให้รายได้จากทรัพย์สินมากกว่ารายจ่าย (ด่าน 1) แล้วไปทำ "ความฝัน" ให้สำเร็จ (ด่าน 2)

- มุมมอง: **3D low poly flat-shaded** กล้อง isometric orthographic — เหมือน "ของเล่นไม้ทาสีวางบนโต๊ะ"
- โทน: ฉากปกติ **เย็น นิ่ง เงียบ** · จะดังและมีสีก็ต่อเมื่อมีเรื่อง (เงินเดือนออก · ปิดดีล · ภัยพิบัติ)
- ผู้เล่นเป็นผู้ใหญ่วัยทำงานคนไทย ไม่ใช่เด็ก — อารมณ์ควรเป็น "จริงจังแต่ไม่เครียดจนหมดสนุก"
- **ห้ามอ้างอิง Cashflow หรือทรัพย์สินทางปัญญาของ Ragnarok Online** ทุกกรณี

### 1.2 พาเลต — สีมาจาก UV ไม่ใช่จากวัสดุ

แผ่นสีคือรูป 256×16 px แบ่งเป็น 32 ช่องแนวนอน ทุกหน้าของเมชต้อง map UV ไปที่ **กลางช่อง**
ที่ต้องการ (v เท่าไหร่ก็ได้ ใช้ 0.5) สูตร: `u = (ลำดับช่อง + 0.5) / 32`

| ช่อง | HEX | u | ใช้กับ |
|---|---|---:|---|
| `neutral_1` | `#F5F1E8` | 0.2969 | ปูนขาว ผนังสว่าง |
| `neutral_2` | `#C9C2B4` | 0.3281 | ปูนหม่น |
| `neutral_3` | `#8B8578` | 0.3594 | หิน คอนกรีตเก่า |
| `neutral_4` | `#4A463F` | 0.3906 | เงา พื้นถนน |
| `neutral_5` | `#23211D` | 0.4219 | ดำ ยางรถ ขอบ |
| `accent_wood` | `#7A3B2E` | 0.4531 | ไม้แดง — ของ "แพง/พรีเมียม" |
| `accent_steel` | `#3B4A5C` | 0.4844 | โลหะเทาน้ำเงิน — ของ "ใช้งาน/เครื่องจักร" · กระจกอาคาร |
| `foliage` | `#4E7A52` | 0.5156 | ใบไม้ พุ่มไม้ |
| `water` | `#2F6D8F` | 0.5469 | น้ำ สระว่ายน้ำ |

**สีต้องห้ามเป็นสีหลักของของในฉาก:** `money #F2B233` · `time #4FC3F7` · `health #F06292`
สามสีนี้จองไว้บอกสถานะผู้เล่นเท่านั้น เอาไปทาตึกแล้วผู้เล่นจะอ่านฉากผิด
(ใช้เป็นจุดเล็กๆ ได้ เช่นไฟท้ายรถ ป้ายไฟ แต่ห้ามเป็นสีตัวของ)

### 1.3 กฎที่เรียนมาแล้วด้วยความเจ็บ — ต้องบอก AI ทุกครั้ง

1. **ทรงต้องอ่านออกที่ 128 px** ไม่ใช่ที่ขนาดจริง — ของทุกชิ้นถูกย่อเป็นไอคอนใน UI ด้วย
   ของหกชิ้นแรกที่ทำเสร็จต้องรื้อทำใหม่เพราะ: ฝากระจกคร่อมทับซิลูเอตจนอ่านเป็น "โต๊ะมีหลังคา" ·
   แผ่นหลังทึบกลืนแท่งกราฟหายทั้งชุด · จานน้ำหนักที่เป็นกล่องอ่านเป็นก้อนดำสองก้อน (ต้องเป็นทรงกระบอก) ·
   แผ่นแบนบนขาอ่านเป็นโต๊ะเสมอ
2. **อาคารกว้างได้ไม่เกินช่องของตัวเองบนถนน** — บ้าน/ฟิตเนส/ธนาคารอยู่ห่างกันแค่ 3 หน่วย
   จึงกว้างได้ราว 2.4 ม. เท่านั้น ให้ไปเอาเนื้อที่คืนทาง **ความลึก (แกน Z)** ซึ่งว่างเสมอ
   เหมือนตึกแถวจริงที่หน้าแคบแต่ลึกมาก · ของหน้าอาคาร (บันได สระ เสาป้าย) ต้องอยู่ในช่องเดียวกัน
3. **รูปทรงต้องบอกว่าอะไรคืออะไรโดยไม่ต้องอ่านป้าย** — เมืองรุ่นแรกเป็นกล่องสิบใบสูงไม่เท่ากัน
   ผู้เล่นแยกธนาคารกับฟิตเนสไม่ออกเลย

### 1.5 ข้อควรรู้: Gemini ผลิต `.glb` ตรงๆ ไม่ได้

ทางที่ใช้ได้จริงและเข้ากับท่อของโปรเจกต์นี้ เรียงจากง่ายไปยาก:

1. **ให้ Gemini เขียนสคริปต์ Blender Python (`bpy`) ต่อทรงจากกล่อง** แล้วเรารันใน Blender → export `.glb`
   วิธีนี้ตรงกับที่โปรเจกต์ทำอยู่แล้ว (ของทั้ง 38 ชิ้นตอนนี้คือเมช "ต่อกล่อง" จากโค้ด GDScript)
   และคุมงบสามเหลี่ยม/UV/ทิศทางได้แม่นกว่าให้คนปั้นมือ
2. **ให้ Gemini สร้างภาพอ้างอิง (concept art)** ของแต่ละชิ้นในสไตล์ low poly flat shaded
   แล้วส่งภาพนั้นให้คนปั้นหรือเครื่องมือ image-to-3D
3. เครื่องมือ text-to-3D แยกต่างหาก แล้วเอามาลดโพลีและ map UV เข้าพาเลตเอง — เสี่ยงหลุดสไตล์ที่สุด

**พรอมป์ต์ตั้งต้นสำหรับข้อ 1 (ก๊อปไปวางได้เลย แล้วแนบสเปกข้อ 1.1–1.4 ตามไป):**

> เขียนสคริปต์ Blender Python (bpy) สร้างโมเดล `<id>` สำหรับเกม low poly flat-shaded
> ข้อกำหนด: หน่วย 1 unit = 1 เมตร · origin ที่ฐาน y=0 · หันหน้า +Z · flat shading เท่านั้น
> (ปิด shade smooth) · วัสดุเดียวชื่อ `flat` · ไม่มี bevel · งบสามเหลี่ยมไม่เกิน `<เพดาน>` tris
> สีทำด้วยการ map UV ไปที่จุด u ที่ระบุ v=0.5 บนแผ่น palette กว้าง 32 ช่อง ตามตารางนี้: `<ตารางข้อ 1.2>`
> ทรงต้องอ่านออกได้แม้ย่อเหลือ 128×128 px · ปิดท้ายด้วยการ export เป็น `.glb`
> ไปที่พาธที่กำหนด โดยไม่ฝัง texture ลงไฟล์

**หลังได้ไฟล์มา:**
```bash
cd godot
# วางไฟล์ที่ world/models/<กลุ่ม>/<id>.glb แล้ว
godot --headless --path . --import
godot --headless --path . --script res://world/tools/model_lint.gd    # ตรวจ tris · วัสดุเดียว · ฐาน y=0 · ชื่อ
godot --headless --path . --script res://world/tools/models_readme.gd # อัปเดตเช็กลิสต์
godot --script res://world/tools/icon_bake.gd                         # อบไอคอนใหม่ (ห้ามใส่ --headless)
WQ_SHOT=/tmp/ui.png godot --path .                                    # เปิดดูของจริงด้วยตา
```
ตัวอบ `.glb` จากโค้ดจะ **ไม่แตะไฟล์ที่ไม่มีตราประทับของมัน** วางทับได้ทีละชิ้นโดยไม่ต้องรอครบ

## 3. เพลงพื้นหลัง — 3 เพลง

### 3.1 สเปกไฟล์บังคับ

- นามสกุลที่ใช้ได้: **`.ogg` (แนะนำ) · `.mp3` · `.wav`** — **Godot นำเข้า `.mp4` ไม่ได้**
  ถ้าได้ไฟล์มาเป็น mp4 ต้องแปลงก่อน: `ffmpeg -i เพลง.mp4 -vn -c:a libvorbis เพลง.ogg`
- **ชื่อไฟล์ = ชื่อช่องเป๊ะ** วางที่ `godot/audio/music/<ช่อง>.ogg`
- **ต้องลูปได้ไร้รอยต่อ** — ท้ายเพลงต่อหัวเพลงต้องไม่มีรอยสะดุด ระบบตั้งจุดลูปที่หัวและท้ายไฟล์
  ตรงๆ ไม่มีการตัดเงียบให้ · เพลงหนึ่งดังต่อเนื่องได้หลายสิบเดือนในเกม
- ยาวเท่าไหร่ก็ได้ **ยิ่งยาวยิ่งไม่น่าเบื่อ** — แนะนำ 2–4 นาทีขึ้นไป
- ดังพอๆ กันทุกช่อง ระบบไม่มี normalize ให้
- ระบบเฟดไขว้ระหว่างเพลงให้เอง 0.8 วินาที — **ห้ามใส่ intro ที่ต้องได้ยินครบถึงจะเข้าใจ**
  เพราะเพลงอาจถูกตัดเข้ากลางเพลงเมื่อไหร่ก็ได้
- ส่งมาแค่ไฟล์เดียวก่อนก็ใช้ได้ — ช่องที่ยังว่างจะยืมไฟล์ของช่องอื่นไปเล่นก่อนอัตโนมัติ

### 3.2 สามช่องและอารมณ์ที่ต้องการ

| ช่อง | ดังตอนไหน | อารมณ์ที่ต้องได้ |
|---|---|---|
| `phase1` | ด่าน 1 (ยังทำงานประจำ หาเงินจากแรงตัวเอง) และตอนอยู่ที่เมนู | **ตั้งใจ มีวินัย ทำซ้ำ** — จังหวะสม่ำเสมอเหมือนเดือนที่วนไป ไม่เร่ง ไม่บีบ ฟังทั้งวันได้ไม่ล้า · เป็นเพลงที่ผู้เล่นจะได้ยินนานที่สุดของเกม |
| `phase2` | ด่าน 2 (ออกจากงานประจำแล้ว กำลังไล่ตามความฝัน) | **โล่ง เปิดกว้าง มีความหวัง** — เหมือนเพลงเดิมที่ปลดโซ่ออก โทนสว่างขึ้น มีที่ว่างมากขึ้น แต่ยังเป็นโลกใบเดียวกับ phase1 |
| `crisis` | สุขภาพตกโซนวิกฤต หรือมีภัยพิบัติค้างอยู่ | **กดดัน ใกล้พัง แต่ยังไม่จบ** — ทุ้มลง จังหวะแน่นขึ้น ไม่ใช่เพลงสยองขวัญ · ผู้เล่นต้องรู้สึกว่า "ต้องรีบแก้" ไม่ใช่ "แพ้แล้ว" |

**ขอให้ทั้งสามเพลงเป็นโลกเดียวกัน** — ใช้ชุดเครื่องดนตรี/โทนเสียงเดียวกัน ต่างกันที่การเรียบเรียง
เพราะระบบสลับเพลงกลางเกมด้วยการเฟดไขว้ ถ้าคนละโลกจะฟังเหมือนเปลี่ยนเกม
ฉากเป็นเมืองไทยร่วมสมัย — ใส่กลิ่นไทยได้ แต่ไม่ต้องเป็นเพลงไทยเดิม

### 3.3 พรอมป์ต์ตั้งต้น

> แต่งเพลงบรรเลงวนลูปสำหรับเกมการเงินแนวบริหารจัดการ ฉากเมืองไทยร่วมสมัย
> มุมมองไอโซเมตริก low poly เหมือนของเล่นไม้บนโต๊ะ · เพลงบรรเลงล้วน ไม่มีเสียงร้อง
> · ต้องฟังต่อเนื่องได้หลายสิบนาทีโดยไม่ล้า ไม่มีท่อนไหนเด่นจนดึงความสนใจไปจากการคิดเลข
> · ต้องลูปได้ไร้รอยต่อ และห้ามมี intro ที่ต้องได้ยินครบถึงจะเข้าใจเพลง
> · ทั้งสามเพลงใช้ชุดเครื่องดนตรีเดียวกัน ต่างกันที่การเรียบเรียงเท่านั้น
> เพลงที่ 1 `phase1`: `<อารมณ์จากตาราง>` · เพลงที่ 2 `phase2`: `<...>` · เพลงที่ 3 `crisis`: `<...>`

**หลังได้ไฟล์มา:**
```bash
cd godot
```

## 4. สรุปสิ่งที่ต้องส่งกลับมา

| กลุ่ม | จำนวน | ฟอร์แมต | วางที่ |
|---|---:|---|---|
| โมเดล 3D | 38 | `.glb` | `godot/world/models/<กลุ่ม>/<id>.glb` |
| เสียงสั้น | 30 | `.wav` mono 16-bit | `godot/audio/sfx/<id>.wav` |
| เพลง | 3 | `.ogg` (หรือ mp3/wav) | `godot/audio/music/<ช่อง>.ogg` |

ทุกอย่าง **ส่งมาทีละชิ้นได้** ไม่ต้องรอครบชุด — ระบบออกแบบมาให้ของเก่ากับของใหม่อยู่ปนกันได้
และตัวอบอัตโนมัติจะไม่แตะไฟล์ที่คนทำมาเอง

หลังวางไฟล์ทุกครั้ง: `cd godot && godot --headless --path . --import` แล้วรันสูทที่เกี่ยวข้อง
(`model_lint` / `audio_check` / `music_check`) — เขียวแล้วค่อยเปิดดู-ฟังด้วยตาและหูจริงอีกรอบ
