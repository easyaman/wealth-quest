# Wealth Quest — Godot project skeleton

เกมการเงิน 2.5D · เงิน · เวลา · สุขภาพ

## เริ่มยังไง

```bash
godot --headless --path . --import                       # ครั้งแรกเท่านั้น — สร้าง class cache
godot --headless --path . --script res://sim/rng_check.gd    # 1) ตัวสุ่มต้องตรงกับ JS ก่อน
godot --headless --path . --script res://sim/headless_sim.gd # 2) สมดุลต้องผ่าน 40–60 เดือน
```

อ่าน `CLAUDE.md` (บริบทและกฎของโปรเจกต์) และ `../WEALTH-QUEST-GDD.md` (เอกสารออกแบบ)

> **ต้อง `--import` ก่อนเสมอในเครื่องใหม่** ไม่งั้น `--script` จะหา `WQData` / `WQMatch` ไม่เจอ
> เพราะ Godot ยังไม่ได้สร้าง global class cache (`.godot/global_script_class_cache.cfg`)

## สถานะ

| ส่วน | สถานะ |
|---|---|
| core (rng, player, match, ai, save) | ✅ **คอมไพล์ผ่านและรันได้จริงแล้ว** (Godot 4.7.1) |
| ตัวสุ่ม | ✅ ตรงกับ `makeRng` ของ JS ทั้ง 5 ค่าอ้างอิง |
| headless sim | ✅ รันครบ 16 อาชีพ — มัธยฐาน 51 เดือน ผ่านเกณฑ์ 40–60 |
| data (ตารางสมดุล) | ครบ สร้างจากเอนจิน JS ที่ผ่านการจำลอง 4,000 เกม |
| ระบบแผนที่/การเดินทาง (ข้อ 3A) | ⬜ **ยังไม่ได้พอร์ต** — เป็นเหตุผลที่ตัวเลขยังเร็วกว่า JS |
| UI | ⬜ placeholder (RichTextLabel + กด Space เพื่อจบตา) |
| ฉาก 2.5D / อาร์ต / เสียง | ⬜ ยังไม่มี |

## บั๊กที่เจอตอนทำให้พอร์ตรันได้ครั้งแรก

| ปัญหา | สาเหตุ |
|---|---|
| ตัวสุ่มให้ค่าไม่ตรงกับ JS **เลยสักค่า** | `next()` แปลจาก JS ตกไป — JS เป็น `(t + imul(...)) ^ t` แต่พอร์ตมาเป็น `& 0xFFFFFFFF` เฉยๆ `^ t` หายไปทั้งตัว |
| `Stack underflow` ตอนรันเกมยาว | `begin_month → run_ai_turns → end_month → begin_month` เรียกซ้อนกันเดือนละชั้น เกมบอทล้วน 100+ เดือนทำ stack ล้น → แก้เป็นลูป |
| คอมไพล์ไม่ผ่าน 20 จุด | `var x := round(...)` — `round()` ของ Godot คืน Variant ต้องใช้ `roundf()` · และ `match_ref` ไม่มี type ทำให้ทุกอย่างที่อ่านผ่านมันเป็น Variant |

## ตัวเลขเทียบกับ JS (เดือนที่ทำความฝันสำเร็จ)

| อาชีพ | GDScript | JS | ต่าง |
|---|---|---|---|
| 💻 โปรแกรมเมอร์ | 37.5 | 39.5 | −5% |
| 👩‍🏫 ครูโรงเรียนรัฐ | 46.6 | 51.5 | −10% |
| 🧹 พนักงานทำความสะอาด | 43.4 | 53.1 | −18% |
| 🩺 แพทย์ | 108.4 | 109.7 | −1% |
| ✈️ นักบินพาณิชย์ | 95.3 | 99.8 | −5% |

**ทุกช่องติดลบหมด = พอร์ตเร็วกว่า JS อย่างเป็นระบบ** ซึ่งอธิบายได้ด้วยเหตุผลเดียว:
GDScript **ยังไม่มีระบบการเดินทาง** ผู้เล่นจึงไม่เสียชั่วโมงไปกับการเดินทางเลย เวลาที่ใช้ได้จึงมากกว่า
และกระทบอาชีพรายได้น้อยมากที่สุด (พนักงานทำความสะอาดมีเวลาว่างน้อยอยู่แล้ว เวลาเดินทางจึงกินสัดส่วนใหญ่)

**พอร์ตระบบแผนที่เสร็จเมื่อไหร่ ตัวเลขควรขยับเข้าหา JS เอง** ถ้าไม่ขยับ แปลว่ามีบั๊กอื่นซ่อนอยู่

## ที่ยังค้างอยู่

  อ้างถึงกันเป็นวง RefCounted จึงไม่ถูกคืนหน่วยความจำ ยังไม่กระทบ sim แต่ต้องแก้ก่อนทำ UI จริง
  (ใช้ `WeakRef` ฝั่งใดฝั่งหนึ่ง)
- ระบบแผนที่/การเดินทาง (ดู `CLAUDE.md` หัวข้อ "ระบบที่เพิ่มเข้ามาหลังพอร์ตรอบแรก")

## หมายเหตุ

โค้ด GDScript ทั้งหมดเขียนโดยแปลจาก `engine.js` ซึ่งเป็น reference implementation ที่ทดสอบแล้ว
ถ้าผลจาก sim ไม่ตรงกับตารางอ้างอิงใน `CLAUDE.md` **ให้เชื่อ `engine.js` เป็นหลัก**
