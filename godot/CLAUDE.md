## ✅ งานแรกทำเสร็จแล้ว — พอร์ตรันได้ ตัวสุ่มตรง

```bash
godot --headless --path . --import                            # ครั้งแรกในเครื่องใหม่
godot --headless --path . --script res://sim/rng_check.gd     # ตัวสุ่มต้องตรงกับ JS
godot --headless --path . --script res://sim/headless_sim.gd  # สมดุลต้องผ่าน 40–60 เดือน
```

**บั๊กที่เจอตอนทำให้รันได้ (แก้แล้วทั้งหมด — ดูรายละเอียดใน `README.md`):**

1. `core/rng.gd` ผิดจริงตามที่คาดไว้ — JS เขียนว่า `t = (t + Math.imul(...)) ^ t`
   แต่พอร์ตมาเป็น `& 0xFFFFFFFF` เฉยๆ **`^ t` หายไปทั้งตัว** ตัวสุ่มจึงไม่ตรงสักค่าเดียว
2. `Stack underflow` ในเกมยาว — วงจร `begin_month → run_ai_turns → end_month → begin_month`
   เรียกซ้อนกันเดือนละชั้น แก้เป็นลูปแล้ว (JS รอดเพราะ stack ของ V8 ใหญ่กว่า)
3. คอมไพล์ไม่ผ่าน 20 จุดจาก `round()` ที่คืน Variant (ต้องใช้ `roundf()`) และ `match_ref` ที่ไม่มี type

**บั๊กที่เจอตอนพอร์ตระบบแผนที่ (แก้แล้วทั้งหมด — ทั้งสามตัวมีมาตั้งแต่พอร์ตรอบแรก):**

4. `pick_template()` กรองเทมเพลตด้วย `downPct[0]` แต่ JS ใช้ `downPct[1]` (ตัวบน)
   เพราะเงินดาวน์จริงสุ่มได้ถึงค่านั้น — กรองด้วยตัวล่างทำให้ดีลที่ยังซื้อไม่ไหวหลุดเข้ามา
   (`make_deal()` ตอนคำนวณเพดานราคาก็ผิดจุดเดียวกัน)
5. `refill_market()` ใช้พื้นเงินดาวน์ที่ถูกที่สุดเป็นเลข `30000` ที่ hardcode ไว้ แต่ค่าจริงจาก
   `data/deals.json` คือ **20000** → ตลาดผลิตดีลคนละใบกับ JS ทั้งที่ตัวสุ่มยังตรงกันอยู่
   ตอนนี้คำนวณจากตารางจริงด้วย `WQData.cheapest_down()`
6. คาบภัยพิบัติลูกแรกเป็น `9 + สุ่ม(10)` แต่ JS เป็น `9 + สุ่ม(8)` → ภัยพิบัติมาคนละเดือน

ข้อ 5 กับ 6 เป็นตัวอย่างของบั๊กที่ **ค่าเฉลี่ยจับไม่ได้** — sim เดิมก็ยังผ่านเกณฑ์ 40–60 เดือน
ต้องเทียบรายเกมเท่านั้นถึงจะเห็น

## ✅ ระบบแผนที่และการเดินทาง (ข้อ 3A) — พอร์ตแล้ว

ข้อมูลอยู่ใน `data/places.json` (สถานที่ · พาหนะ · อุปกรณ์ · แพ็กเกจฟิตเนส/รีสอร์ต) โค้ดอยู่ใน `core/player.gd`:

- `place` + `travel_to(place_id)` — เวลา = `max(1, round(|xA−xB| × travel_rate × ตัวคูณพาหนะ))`
- `place_for(act)` / `can_do_here(act)` — ทุกการกระทำผูกกับสถานที่ · 📱 ทำธุรกรรมธนาคารได้ทุกที่
  · 💻 เรียนและรับ freelance ที่บ้านได้
- `buy_vehicle()` / `buy_device()` — พาหนะลด `commute` ประจำด้วย ไม่ใช่แค่เวลาเดินทาง
  และเพิ่ม `get_upkeep_cost()` เข้าไปในรายจ่ายทุกเดือน
- `exercise(pack_id)` / `vacation(pack_id)` — รีสอร์ตให้ `shield` ที่ไปคูณลดโอกาสเกิดเหตุการณ์ร้าย
- `WQAi.best_move()` วางแผนเส้นทางแล้ว: คะแนน = ผลตอบแทน ÷ (เวลาทำ + เวลาเดินทาง)
- สิ้นเดือน: `place = "home"`, `travel_used = 0`, `gym_pack = ""`, `shield = 0`

**ให้ `../engine.js` เป็น reference เสมอ** — มันคือฉบับที่ผ่านการจำลองแล้ว

### ⚠️ `cands` ใน `best_move` ห้ามใช้ `sort_custom`

JS ใช้ `Array.prototype.sort` ซึ่ง **stable** พอคะแนนเสมอกันจึงได้ตัวที่ใส่เข้าไปก่อน
`sort_custom` ของ Godot ไม่ stable — ถ้าเปลี่ยนไปใช้ ผลจะหลุดจาก `engine.js` แบบหาสาเหตุยาก
โค้ดปัจจุบันจึงวนหาค่ามากสุดแบบ "ตัวแรกชนะเมื่อเสมอ" แทน

## ตรวจว่ายังตรงกับ JS (ทำทุกครั้งที่แก้ core หรือ data)

```bash
node ../tools/parity_dump.js 60 > /tmp/js.json
godot --headless --path . --script res://sim/parity_dump.gd -- 60 | grep '^ROW' > /tmp/gd.txt
node ../tools/parity_check.js /tmp/js.json /tmp/gd.txt      # ต้องขึ้น "ตรงกันทุกเกม ✅"
```

ถ้าไม่ตรง ให้หาว่าเกมไหนแตกก่อน แล้วไล่ทีละเดือนด้วยคู่เครื่องมือ trace:

```bash
node ../tools/trace_dump.js <job_id> <seed_index>
godot --headless --path . --script res://sim/trace_dump.gd -- <job_id> <seed_index>
```

ทั้งสองพิมพ์สถานะรายเดือน (`T <i> rng=… cash=… hp=… …`) ที่จุดเดียวกันเป๊ะ
บรรทัดแรกที่ต่างกันคือเดือนที่พอร์ตเริ่มเพี้ยน ใส่ `WQ_TRACE_AI=1` เพิ่มเพื่อดูการตัดสินใจของบอทรายครั้ง
(`A m=… -> tag@place …`) **ค่า `rng` ฝั่ง JS เป็น int32 มีเครื่องหมาย ฝั่ง Godot ไม่มี** — ต่างกัน 2³² ถือว่าตรงกัน

## กฎเหล็กของโปรเจกต์

1. **`core/` ห้ามรู้จัก UI เลย** — ห้าม `preload` อะไรจาก `ui/` หรือ `world/` ห้ามเรียก `get_node`
   นี่คือสิ่งเดียวที่ทำให้รันจำลอง 4,000 เกมได้ในไม่กี่วินาที ถ้าพังข้อนี้ จะปรับสมดุลไม่ได้อีกเลย
2. **ตัวเลขสมดุลอยู่ใน `data/*.json` เท่านั้น** ห้าม hardcode ตัวเลขในโค้ด
3. **แก้ตัวเลขเมื่อไหร่ ต้องรัน headless sim ทุกครั้ง** ก่อน commit
4. **state ของตัวสุ่มต้องอยู่ในไฟล์เซฟเสมอ** ไม่งั้นผู้เล่น save-scum ได้
5. UI ต้อง subscribe สัญญาณ (`month_ended`, `changed`, `disaster_started`) **อย่า redraw ทั้งหน้าจอทุกเฟรม**

## UI

- ทุกวิดเจ็ตรับผู้เล่นผ่าน `bind(player)` แล้ว subscribe สัญญาณ `changed` เอง
  **ห้าม refresh ทุกเฟรม** และ `bind()` ซ้ำต้องถอดสัญญาณของคนเดิมออกก่อนเสมอ
- ลบลูกของ container ด้วย `remove_child()` + `free()` **อย่าใช้ `queue_free()`**
  เพราะ `changed` ยิงได้หลายครั้งในเฟรมเดียว โหนดที่รอลบยังนับเป็นลูกอยู่ รายการจะซ้อนกัน
- **แต่ถ้าวิดเจ็ตต้องสร้างปุ่มใหม่ทั้งแผง ให้เลื่อนไปสิ้นเฟรมด้วย `call_deferred`**
  (ดู `WQDealMarket._queue_rebuild`) ห้าม `free()` ปุ่มทิ้งระหว่างที่ปุ่มนั้นกำลังส่งสัญญาณ `pressed`
  อยู่ ใช้ธงกันคิวซ้อนไว้ด้วย ไม่งั้นสร้างใหม่หลายรอบต่อเฟรม
- อะไรที่ยาวเกินจอต้องอยู่ใน `ScrollContainer` — ตลาดดีลมีได้ถึง 11 ใบ ถ้าไม่มีสกรอลล์
  การ์ดแถวล่างจะกดไม่ได้เลย
- **อีโมจิขาวดำ (🏁 📱 🛒 🏋️) จมหายไปกับพื้นเข้มของเกม** ดูเหมือนกล่องเปล่าทั้งที่ฟอนต์มีตัวอักษรนั้น
  อีโมจิที่มีสีในตัว (⏳ 📍 ❤️ 💡 🔥 🎉 🏆) ใช้ได้ปกติ — อีโมจิที่มาจาก `data/*.json` ผ่านมาแล้ว
  ให้เช็กด้วยตาก่อนใส่อีโมจิลงในข้อความที่เขียนเองในโค้ด
- **หน้าจอเต็มจอที่ลอยทับเกม (ทอยความฝัน · บันทึก/โหลด) ต้องบล็อกทางลัดคีย์บอร์ดด้วย**
  ไม่ใช่แค่บังเมาส์ — `ui/main.gd` เช็ก `dream_screen`/`save_panel` ก่อนรับ Space ทุกครั้ง
  ส่วนการ์ดสอนตรงข้ามกัน: ต้อง `MOUSE_FILTER_IGNORE` ทั้งแผ่น เพราะผู้เล่นต้องเล่นเกมต่อได้ระหว่างอ่าน
- Godot มากับฟอนต์ที่ไม่มีสระ/วรรณยุกต์ไทย ข้อความจะกลายเป็นกล่องเปล่า
  `ui/main.gd` จึงยืมฟอนต์ไทยจากระบบผ่าน `SystemFont` — **ตอนจะปล่อยจริงต้องฝังฟอนต์ที่มีสิทธิ์ใช้งาน**
  ลงในโปรเจกต์ ไม่งั้นเครื่องที่ไม่มีฟอนต์ไทยจะอ่านไม่ออก

### กฎเพิ่มสำหรับ `world/`

1. `world/` **อ่าน** state ผ่าน `bind(player|match)` + สัญญาณเท่านั้น **ห้ามแก้ state** — คลิกอาคาร → ยิง
   `place_clicked(place_id)` ให้ `ui/main.gd` เป็นคนเรียก `travel_to()`
2. `core/` และ `sim/` ห้ามอ้างถึง `world/` — headless sim ต้องรันได้โดยไม่โหลด 3D เลย
   (`sim/world_check.gd` บังคับกฎนี้ให้อัตโนมัติแล้ว)
3. `randf()` ใน `world/` ใช้ได้เฉพาะแอนิเมชันที่ไม่กระทบสถานะและไม่กระทบการอ่านฉาก
   — ตำแหน่งและความสูงอาคารคำนวณจาก `x` ใน `places.json` เสมอ ไม่งั้นเมืองจะสลับหน้าตาทุกครั้งที่เปิดเกม
4. แอนิเมชันเดินไปอาคารต้องข้ามได้ (สั่งซ้ำระหว่างเดิน = วาร์ป) — ห้ามให้ผู้เล่นรอแอนิเมชัน
5. ตัวเลขบนแท่นโชว์ต้องมาจาก `core` — ดีลใช้ `WQPlayer.deal_terms()` ตัวเดียวกับที่ `deal_card` ใช้
   และเป็นสูตรชุดเดียวกับตอน `close_deal()` หักเงินจริง
6. โมเดลใหม่ทุกชิ้นต้องผ่าน `model_lint` — งบสามเหลี่ยม · วัสดุเดียว · ฐานอยู่ที่ y=0 · ชื่อโหนด = id
   และ `world/models/README.md` ต้องสร้างใหม่ด้วย `models_readme.gd` ทุกครั้งที่รายการเปลี่ยน
7. สีของเมชมาจากการ map UV ไปที่ช่องบน `palette.png` (`WQPalette.slot_u()`)
   **ห้ามตั้ง `albedo_color` รายชิ้น** ยกเว้นกล่องเปล่าที่ยังไม่มีโมเดล
8. ไอคอนใน UI ต้องผ่าน `WQIcon` เสมอ ห้ามโหลด `ui/theme/icons/*.png` ตรงๆ
   เพราะ `WQIcon` เป็นคนจัดการ fallback เป็นอีโมจิและตั้ง filter ให้ย่อรูปแล้วไม่แตก
9. ก่อนจบทุก Sprint: `godot --headless --quit` + sim ทั้งชุด + `WQ_SHOT=/tmp/ui.png godot` แล้วเปิดดูภาพจริง

### ที่ของจริงต่างจาก ART-DIRECTION / CLAUDE-CODE-BRIEF — อย่าแก้กลับ

- **`icon_bake` รัน headless ไม่ได้** โหมด headless ของ Godot ใช้ตัวเรนเดอร์หลอก
  `viewport.get_texture().get_image()` คืน `null` ต้องรันแบบเปิดหน้าต่าง (สคริปต์ปิดตัวเองให้)
- **API ของแท่นโชว์ชื่อ `show_item()` ไม่ใช่ `show()`** เพราะ `Control` มี `show()` ของตัวเองอยู่แล้ว
  ทับแล้ว GDScript จะ parse ไม่ผ่านทั้งไฟล์
- **id ของพาหนะคือ `public · moto · usedcar · newcar · luxury`** ตาม `data/places.json`
  (ART-DIRECTION ข้อ 3 เขียน `bus/motorbike/car_used/...` ไว้ผิด) — กฎ "ชื่อไฟล์ = id ใน data" ชนะเสมอ
- **ดีลไม่มี id คงที่** (`id` เป็นเลขรันไทม์) โมเดลและไอคอนของดีลจึงอ้างด้วย *ประเภท* แทน
  → `world/models/assets/<kind>.glb` เช่น `micro.glb`, `realestate.glb`
- **`SubViewport` ทุกตัวต้องตั้ง `own_world_3d = true`** ค่าเริ่มต้นคือใช้โลก 3D ร่วมกับพ่อ
  ถ้าลืม ฉากเมืองกับแท่นโชว์จะไปกองในโลกใบเดียวกัน แล้วถนนกับตึกจะโผล่หลังของบนแท่นโชว์
  (`world_check` ตรวจข้อนี้ให้แล้ว)
- **ฉากเมืองห้ามกว้างเต็มจอ** — กล้อง orthographic size 22 ล็อกความสูงไว้ที่ 22 หน่วย
  ความกว้างที่เห็นจึงผันตามอัตราส่วนภาพล้วนๆ · เต็มจอ 16:9 = เห็นกว้างราว 140 หน่วย
  ขณะที่ถนนทั้งเส้นยาวแค่ 50 เมืองจะลอยอยู่กลางพื้นว่าง — `ui/main.gd` จึงบีบแถบฉาก
  ไว้ที่ 1000×300 (ราว 3:1) ด้วย `CenterContainer`
- **`claim_dream()` เดิมไม่ยิง `changed`** — เป็นการเปลี่ยนสถานะที่สำคัญที่สุดของเกม
  แต่ UI ไม่มีทางรู้ แผงเป้าหมายจึงค้างอยู่ที่ "ด่าน 2" ทั้งที่ผู้เล่นชนะไปแล้ว (แก้แล้ว)
  เวลาเพิ่มเมธอดที่เปลี่ยน state ใน `core/player.gd` **ต้องยิง `changed` เสมอ**
- **แก้เมชแล้วต้องอบ "ไอคอน" ใหม่ด้วย ไม่ใช่แค่ `.glb`** — ไอคอนของสถานที่ทั้งสิบถูกอบไว้
  ตั้งแต่ Sprint A ตอนที่อาคารยังเป็นกล่องเปล่า ทุกไฟล์จึงเหมือนกันหมด (`bank.png` กับ
  `estate.png` มี md5 เดียวกันเป๊ะ) แต่ไม่มีใครสังเกตเพราะ UI ยังไม่มีที่ไหนโชว์ไอคอนสถานที่
  พอทำแผงเดินทางถึงโผล่มาเป็นก้อนเทาสิบก้อนเหมือนกัน → `godot --script res://world/tools/icon_bake.gd`
  (**ห้ามใส่ `--headless`**) แล้ว `--import` ตาม
- **ปุ่มที่มีทั้งไอคอนและข้อความยาว ต้องกว้างพอ** — `Button` ที่ `expand_icon = true`
  จะบีบไอคอนจนหายไปเลยถ้าข้อความกินที่หมด (เจอจริงกับ "ศูนย์อสังหาฯ & ตลาดธุรกิจ"
  ที่ไอคอนหายไปแถวเดียวในสิบแถว) · ติดไอคอนให้ปุ่มด้วย `WQIcon.decorate_button()` เสมอ
- **แก้เมชต่อกล่องแล้วต้องอบ `.glb` ใหม่** — ลำดับการหาโมเดลคือ `.glb` มาก่อนเสมอ
  ตอนนี้ทั้ง 21 ชิ้นมีไฟล์ `.glb` แล้ว **การแก้ `kitbash*.gd` เฉยๆ จะไม่เปลี่ยนอะไรในเกม**
  ต้องรัน `glb_export.gd` แล้ว `--import` ตามทุกครั้ง
- **ห้ามฝังแผ่น palette ลงในไฟล์ `.glb`** — ตัวนำเข้าของ Godot จะแกะรูปออกมาเป็น
  `<id>_palette.png` กองอยู่ข้างโมเดลทุกชิ้น (เคยเกิดจริง: ไฟล์งอกมา 42 ไฟล์)
  และแย่กว่านั้นคือ palette ถูกก๊อปไป 21 ชุด แก้สีที่ `palette.gd` แล้วโมเดลไม่เปลี่ยนตาม
  ตัวอบจึงถอด texture ออกก่อนเขียนไฟล์ แล้ว `WQShowcase.model_for()` เป็นคนสวม `flat.tres`
  ให้ทุกโมเดลที่โหลดจาก `.glb` — เปลี่ยนสีทั้งเกมจากไฟล์เดียวจึงยังทำได้เหมือนเดิม
- **`world/models/README.md` แยก "ปั้นแล้ว" ออกจาก "อบจากโค้ด"** — อย่าไปนับ `.glb (อบ)`
  เป็นงานอาร์ตที่เสร็จแล้ว มันคือทรงเดียวกับที่โค้ดสร้าง แค่ย้ายมาเป็นไฟล์
- **อาคารกว้างได้ไม่เกิน "ช่องของตัวเอง" บนถนน** — `x` ใน `places.json` บางคู่ห่างกันแค่ 3 หน่วย
  (บ้าน 50 · ฟิตเนส 56 · ธนาคาร 62) สามหลังนั้นจึงกว้างได้ราว 2.4 ม. เท่านั้น แล้วไปเอาเนื้อที่คืน
  ทางความลึก (แกน Z) ซึ่งว่างเสมอ · ของหน้าอาคาร (บันได สระ เสาป้าย เสาธง) ก็ต้องอยู่ในช่องเดียวกัน
  ถ้าเผลอวางไว้ "ข้าง" อาคาร มันจะไปโผล่ในเขตของเพื่อนบ้าน
  → `world_check` มีเทสต์ **"อาคารไม่มีหลังไหนกินเนื้อที่ทับกัน"** คุมไว้แล้ว วัดจาก `WQPlaceNode.bounds`
  (ไม่ใช่ AABB ของทั้งโหนด เพราะโหนดมีวงไฟไฮไลต์กว้างกว่าตัวอาคาร)
- **ถนนกับทางเท้าอยู่ที่ z 5–12 ไม่ใช่ z 3.4 อย่างใน Sprint A** — เพราะหน้าอาคารยื่นออกมาถึง z=5
  (สระว่ายน้ำของโรงแรม) ถ้าถนนอยู่ใกล้กว่านั้น บันไดธนาคารกับเสาป้ายห้างจะไปตั้งกลางถนน
- **ช่องสีเพิ่มได้ แต่ต้อง "ต่อท้าย" `WQPalette.SLOTS` เท่านั้น** — Sprint C เพิ่ม `foliage` กับ `water`
  เพราะเขียว/ฟ้าที่มีอยู่ (WIN / TIME) ถูกจองความหมายไว้แล้ว เอาไปทาต้นไม้กับน้ำไม่ได้
  แทรกกลางรายการเมื่อไหร่ UV ของเมชเดิมจะชี้ผิดช่องทั้งหมด (มีที่ว่างถึง 32 ช่อง ใช้จริง 18)
- **`WQSetup.roll_start()` สับไพ่ไม่ตรงกับ `engine.js` โดยตั้งใจ** — ฝั่ง JS ใช้ `sort(() => rng()-0.5)`
  ซึ่งผลขึ้นกับอัลกอริทึม sort ของ V8 พอร์ตให้ตรงเป๊ะไม่ได้ ที่นี่ใช้ Fisher–Yates แทน
  ไม่กระทบ parity เพราะ `sim/parity_dump.gd` ระบุ `job_id` ตรงๆ ไม่ได้ผ่านการทอยเต๋า
- **`WQSetup.job_preview()` ถามค่าใช้จ่ายรวมไม่ได้** — `get_debt_payments()` ต้องอ่านตัวคูณดอกเบี้ย
  จากภัยพิบัติผ่าน `match_ref.get_mods()` แต่ผู้เล่นตัวอย่างในหน้าเลือกอาชีพยังไม่มี match
  ที่หน้านั้นจึงโชว์ `monthly_burden` = `job.fixed + job.food` ซึ่งเป็นข้อมูลดิบของอาชีพ ไม่ใช่สูตร
- **เมชตัวละครยัง 340 tris ต่ำกว่างบ 800 ที่ ART-DIRECTION วางไว้** — `model_lint` เตือนไว้แล้ว
  (เป็นข้อสังเกต ไม่ใช่ผิด) ตั้งใจปล่อยไว้ให้ `.glb` จริงมาเติมรายละเอียดส่วนที่เหลือ
- **มุมไฟหลักคือ yaw +30° ไม่ใช่ −35°** ตอนแรกตั้งตามคำว่า "บนซ้าย" ตรงๆ แล้วแสงไปตกด้านหลัง
  ที่กล้องมองไม่เห็น หน้าที่เห็นได้แต่ ambient สีฟ้า ของทุกชิ้นเลยออกมาเป็นสีน้ำเงินหมด
  ไม่ว่าจะ map UV ไปที่ช่องสีไหนก็ตาม
- **ไอคอนต้องเปิด mipmap** (`mipmaps/generate=true` ใน `.import`) เพราะอบมาที่ 128px
  แล้ว UI ย่อเหลือ ~18px — `icon_bake` ตามไปแก้ค่าให้เองทุกครั้งที่รัน
- **Godot เปิด `_process` ให้เองตอนโหนดเข้าฉาก ถ้าสคริปต์มี `_process` อยู่** — `set_process(false)`
  ที่เขียนไว้ใน `_init()` จึงถูกทับ ต้องสั่งใน `_ready()` แทน (เจอจริงกับ `WQDice`: หน้าจอขึ้น
  "ทอยได้ 6" แต่ลูกเต๋าโชว์หนึ่งจุด เพราะ `_process` เดินแล้วลากหน้าเต๋ากลับไปที่ค่าเริ่มต้น)
- **ห้าม `free()` หน้าจอทิ้งใน handler ของปุ่มที่อยู่ในหน้าจอนั้น** — ตัวมันยังถูกล็อกอยู่
  Godot ปฏิเสธ ("Object is locked and can't be freed") แล้ว **ทั้งฟังก์ชันหลุดกลางคัน**
  ผลคือกดปุ่มแล้วเงียบ ไม่มี error ให้เห็นในเกม · ใช้ `remove_child()` + `call_deferred("free")`
  (`ui/main.gd` มี `_close_screen()` ไว้ให้แล้ว) — ของเดิมพลาดข้อนี้กับหน้าเลือกอาชีพมาตลอด
- **โหนดที่ไม่ได้อยู่ใน Container "โตแล้วไม่หดกลับ"** — `get_combined_minimum_size()` เป็นแค่พื้น
  ไม่ใช่เพดาน การ์ดสอนที่เคยสูง 656 px จากสเต็ปข้อความยาว จะค้างความสูงนั้นไว้ให้สเต็ปสั้นๆ
  แล้วไปโผล่กลางจอ · ต้องตั้ง `size` เองทุกครั้งที่เนื้อหาเปลี่ยน
- **วงแหวนไฮไลต์ต้องเกาะ `item_rect_changed` ของวิดเจ็ตเป้าหมาย ไม่ใช่ `value_changed` ของสกรอลล์**
  ตอนที่แถบสกรอลล์บอกว่าค่าเปลี่ยน ลูกของมันยังไม่ถูกจัดตำแหน่งใหม่ วงแหวนจะเพี้ยนไปเท่าระยะที่เพิ่งเลื่อน
- **`saved_at` ละเอียดแค่วินาที ใช้เรียงลำดับ autosave ไม่ได้** — ผู้เล่นที่กด Space รัวๆ
  จบสามเดือนในวินาทีเดียวจะได้เวลาเท่ากันหมด แล้ววงสามช่องจะยุบเหลือช่องเดียว
  `write_auto()` จึงเรียงด้วยตัวนับ `seq` ที่อ่านจากไฟล์จริง
- **`WQSave.dir` เป็น `static var` เพราะเทสต์ต้องเขียนคนละที่กับไฟล์เซฟจริง** (`user://saves_test`)
  ถ้าเทสต์เขียนทับ `user://saves` วันไหนที่รันบนเครื่องที่มีเกมเซฟจริงอยู่ ของผู้เล่นหายทันที
- **`palette.png.import` ตั้ง `detect_3d/compress_to=0` ไว้** ห้ามเปลี่ยน —
  ไม่งั้น Godot จะ reimport เป็น texture บีบอัดตอนเอาไปใช้ใน 3D แล้วสีในพาเลตจะเพี้ยนทีละนิด
