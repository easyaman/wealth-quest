## โปรเจกต์นี้คืออะไร

## ✅ งานแรกทำเสร็จแล้ว — พอร์ตรันได้ ตัวสุ่มตรง

```bash
godot --headless --path . --import                            # ครั้งแรกในเครื่องใหม่
godot --headless --path . --script res://sim/rng_check.gd     # ตัวสุ่มต้องตรงกับ JS
godot --headless --path . --script res://sim/headless_sim.gd  # สมดุลต้องผ่าน 40–60 เดือน
```

**บั๊กที่เจอตอนทำให้รันได้ (แก้แล้วทั้งหมด — ดูรายละเอียดใน `README.md`):**

1. `core/rng.gd` ผิดจริงตามที่คาดไว้ — JS เขียนว่า `t = (t + Math.imul(...)) ^ t`
   แต่พอร์ตมาเป็น `& 0xFFFFFFFF` เฉยๆ **`^ t` หายไปทั้งตัว** ตัวสุ่มจึงไม่ตรงสักค่าเดียว
2. `Stack underflow` ในเกมยาว — วงจร `begin_month → run_ai_turns → end_month → begin_month`
   เรียกซ้อนกันเดือนละชั้น แก้เป็นลูปแล้ว (JS รอดเพราะ stack ของ V8 ใหญ่กว่า)
3. คอมไพล์ไม่ผ่าน 20 จุดจาก `round()` ที่คืน Variant (ต้องใช้ `roundf()`) และ `match_ref` ที่ไม่มี type

**บั๊กที่เจอตอนพอร์ตระบบแผนที่ (แก้แล้วทั้งหมด — ทั้งสามตัวมีมาตั้งแต่พอร์ตรอบแรก):**

4. `pick_template()` กรองเทมเพลตด้วย `downPct[0]` แต่ JS ใช้ `downPct[1]` (ตัวบน)
   เพราะเงินดาวน์จริงสุ่มได้ถึงค่านั้น — กรองด้วยตัวล่างทำให้ดีลที่ยังซื้อไม่ไหวหลุดเข้ามา
   (`make_deal()` ตอนคำนวณเพดานราคาก็ผิดจุดเดียวกัน)
5. `refill_market()` ใช้พื้นเงินดาวน์ที่ถูกที่สุดเป็นเลข `30000` ที่ hardcode ไว้ แต่ค่าจริงจาก
   `data/deals.json` คือ **20000** → ตลาดผลิตดีลคนละใบกับ JS ทั้งที่ตัวสุ่มยังตรงกันอยู่
   ตอนนี้คำนวณจากตารางจริงด้วย `WQData.cheapest_down()`
6. คาบภัยพิบัติลูกแรกเป็น `9 + สุ่ม(10)` แต่ JS เป็น `9 + สุ่ม(8)` → ภัยพิบัติมาคนละเดือน

ข้อ 5 กับ 6 เป็นตัวอย่างของบั๊กที่ **ค่าเฉลี่ยจับไม่ได้** — sim เดิมก็ยังผ่านเกณฑ์ 40–60 เดือน
ต้องเทียบรายเกมเท่านั้นถึงจะเห็น

## ✅ ระบบแผนที่และการเดินทาง (ข้อ 3A) — พอร์ตแล้ว

ข้อมูลอยู่ใน `data/places.json` (สถานที่ · พาหนะ · อุปกรณ์ · แพ็กเกจฟิตเนส/รีสอร์ต) โค้ดอยู่ใน `core/player.gd`:

- `place` + `travel_to(place_id)` — เวลา = `max(1, round(|xA−xB| × travel_rate × ตัวคูณพาหนะ))`
- `place_for(act)` / `can_do_here(act)` — ทุกการกระทำผูกกับสถานที่ · 📱 ทำธุรกรรมธนาคารได้ทุกที่
  · 💻 เรียนและรับ freelance ที่บ้านได้
- `buy_vehicle()` / `buy_device()` — พาหนะลด `commute` ประจำด้วย ไม่ใช่แค่เวลาเดินทาง
  และเพิ่ม `get_upkeep_cost()` เข้าไปในรายจ่ายทุกเดือน
- `exercise(pack_id)` / `vacation(pack_id)` — รีสอร์ตให้ `shield` ที่ไปคูณลดโอกาสเกิดเหตุการณ์ร้าย
- `WQAi.best_move()` วางแผนเส้นทางแล้ว: คะแนน = ผลตอบแทน ÷ (เวลาทำ + เวลาเดินทาง)
- สิ้นเดือน: `place = "home"`, `travel_used = 0`, `gym_pack = ""`, `shield = 0`

**ให้ `../engine.js` เป็น reference เสมอ** — มันคือฉบับที่ผ่านการจำลองแล้ว

### ⚠️ `cands` ใน `best_move` ห้ามใช้ `sort_custom`

JS ใช้ `Array.prototype.sort` ซึ่ง **stable** พอคะแนนเสมอกันจึงได้ตัวที่ใส่เข้าไปก่อน
`sort_custom` ของ Godot ไม่ stable — ถ้าเปลี่ยนไปใช้ ผลจะหลุดจาก `engine.js` แบบหาสาเหตุยาก
โค้ดปัจจุบันจึงวนหาค่ามากสุดแบบ "ตัวแรกชนะเมื่อเสมอ" แทน

## ตรวจว่ายังตรงกับ JS (ทำทุกครั้งที่แก้ core หรือ data)

```bash
node ../tools/parity_dump.js 60 > /tmp/js.json
godot --headless --path . --script res://sim/parity_dump.gd -- 60 | grep '^ROW' > /tmp/gd.txt
node ../tools/parity_check.js /tmp/js.json /tmp/gd.txt      # ต้องขึ้น "ตรงกันทุกเกม ✅"
```

ถ้าไม่ตรง ให้หาว่าเกมไหนแตกก่อน แล้วไล่ทีละเดือนด้วยคู่เครื่องมือ trace:

```bash
node ../tools/trace_dump.js <job_id> <seed_index>
godot --headless --path . --script res://sim/trace_dump.gd -- <job_id> <seed_index>
```

ทั้งสองพิมพ์สถานะรายเดือน (`T <i> rng=… cash=… hp=… …`) ที่จุดเดียวกันเป๊ะ
บรรทัดแรกที่ต่างกันคือเดือนที่พอร์ตเริ่มเพี้ยน ใส่ `WQ_TRACE_AI=1` เพิ่มเพื่อดูการตัดสินใจของบอทรายครั้ง
(`A m=… -> tag@place …`) **ค่า `rng` ฝั่ง JS เป็น int32 มีเครื่องหมาย ฝั่ง Godot ไม่มี** — ต่างกัน 2³² ถือว่าตรงกัน

## กฎเหล็กของโปรเจกต์

1. **`core/` ห้ามรู้จัก UI เลย** — ห้าม `preload` อะไรจาก `ui/` หรือ `world/` ห้ามเรียก `get_node`
   นี่คือสิ่งเดียวที่ทำให้รันจำลอง 4,000 เกมได้ในไม่กี่วินาที ถ้าพังข้อนี้ จะปรับสมดุลไม่ได้อีกเลย
2. **ตัวเลขสมดุลอยู่ใน `data/*.json` เท่านั้น** ห้าม hardcode ตัวเลขในโค้ด
3. **แก้ตัวเลขเมื่อไหร่ ต้องรัน headless sim ทุกครั้ง** ก่อน commit
4. **state ของตัวสุ่มต้องอยู่ในไฟล์เซฟเสมอ** ไม่งั้นผู้เล่น save-scum ได้
5. UI ต้อง subscribe สัญญาณ (`month_ended`, `changed`, `disaster_started`) **อย่า redraw ทั้งหน้าจอทุกเฟรม**
6. **เสียงของเหตุการณ์ในเกมมาจากสัญญาณเท่านั้น** — `ui/` เรียกได้แค่ `WQAudio.ui()` ซึ่งรับเฉพาะ id
   ใน `WQBank.UI_IDS` (เสียง UI ล้วน: คลิก · เปิด/ปิดแผง · ลูกเต๋า · เซฟ/โหลด) ถ้าปล่อยให้ `ui/`
   ยิงเสียงเหตุการณ์เองได้ วันหนึ่งจะมีเสียง "ปิดดีลสำเร็จ" ดังตอนที่เงินไม่พอ
7. **เพิ่มเมธอดที่เปลี่ยน state ใน `core/player.gd` ต้องยิง `changed` และ `acted(kind)` เสมอ**
   และ **ห้ามยิง `acted` ตอนคืน `_fail()`** ไม่งั้นผู้เล่นจะได้ยินเสียง "สำเร็จ" ตอนที่ทำไม่ได้

## UI

- ทุกวิดเจ็ตรับผู้เล่นผ่าน `bind(player)` แล้ว subscribe สัญญาณ `changed` เอง
  **ห้าม refresh ทุกเฟรม** และ `bind()` ซ้ำต้องถอดสัญญาณของคนเดิมออกก่อนเสมอ
- ลบลูกของ container ด้วย `remove_child()` + `free()` **อย่าใช้ `queue_free()`**
  เพราะ `changed` ยิงได้หลายครั้งในเฟรมเดียว โหนดที่รอลบยังนับเป็นลูกอยู่ รายการจะซ้อนกัน
- **แต่ถ้าวิดเจ็ตต้องสร้างปุ่มใหม่ทั้งแผง ให้เลื่อนไปสิ้นเฟรมด้วย `call_deferred`**
  (ดู `WQDealMarket._queue_rebuild`) ห้าม `free()` ปุ่มทิ้งระหว่างที่ปุ่มนั้นกำลังส่งสัญญาณ `pressed`
  อยู่ ใช้ธงกันคิวซ้อนไว้ด้วย ไม่งั้นสร้างใหม่หลายรอบต่อเฟรม
- **วิดเจ็ตที่ต่อ `changed` เข้ากับ `refresh()` ตรงๆ (ไม่ผ่าน `call_deferred`) ห้ามสร้างปุ่มใหม่ใน
  `refresh()`** — การกดปุ่มจะวิ่งกลับมาถึง `refresh()` ทันทีขณะที่ปุ่มยังส่งสัญญาณอยู่
  `WQTimeBudget` จึงสร้างปุ่มนอน/อาหารครั้งเดียวแล้วอัปเดตแต่ข้อความ (รายการมาจาก data ที่ไม่เปลี่ยน)
  ส่วนแผงที่รายการเปลี่ยนได้จริงให้ใช้ `_queue_rebuild` แบบ deferred เหมือน `WQActionPanel`
- **ป้ายราคาเป็นชั่วโมงต้องอยู่บนปุ่มเสมอ (กฎ 12.2.3) และต้องเป็นราคาของสิ่งที่กดแล้วจะเกิดขึ้นจริง**
  ปุ่มการกระทำที่ยังไปไม่ถึงที่ จะกลายเป็น "ปุ่มเดินทาง" ราคาบนปุ่มจึงต้องเป็นค่าเดินทาง
  ส่วนราคาของการกระทำย้ายไปอยู่บรรทัดใต้ปุ่ม (ดู `WQActionPanel._act_row`)
- **ปุ่มที่กดไม่ได้ต้องบอกเหตุผลทุกครั้ง** ไม่ปล่อยให้เทาเฉยๆ — ผู้เล่นจะคิดว่าเกมพัง
  เงื่อนไขที่เช็กต้องตรงกับที่ core ปฏิเสธจริง ไม่ใช่เดาเอง
- อะไรที่ยาวเกินจอต้องอยู่ใน `ScrollContainer` — ตลาดดีลมีได้ถึง 11 ใบ ถ้าไม่มีสกรอลล์
  การ์ดแถวล่างจะกดไม่ได้เลย
- **อีโมจิขาวดำ (🏁 📱 🛒 🏋️) จมหายไปกับพื้นเข้มของเกม** ดูเหมือนกล่องเปล่าทั้งที่ฟอนต์มีตัวอักษรนั้น
  อีโมจิที่มีสีในตัว (⏳ 📍 ❤️ 💡 🔥 🎉 🏆) ใช้ได้ปกติ — อีโมจิที่มาจาก `data/*.json` ผ่านมาแล้ว
  ให้เช็กด้วยตาก่อนใส่อีโมจิลงในข้อความที่เขียนเองในโค้ด
- **หน้าจอเต็มจอที่ลอยทับเกม (ทอยความฝัน · บันทึก/โหลด) ต้องบล็อกทางลัดคีย์บอร์ดด้วย**
  ไม่ใช่แค่บังเมาส์ — `ui/main.gd` เช็ก `dream_screen`/`save_panel` ก่อนรับ Space ทุกครั้ง
  ส่วนการ์ดสอนตรงข้ามกัน: ต้อง `MOUSE_FILTER_IGNORE` ทั้งแผ่น เพราะผู้เล่นต้องเล่นเกมต่อได้ระหว่างอ่าน
- Godot มากับฟอนต์ที่ไม่มีสระ/วรรณยุกต์ไทย ข้อความจะกลายเป็นกล่องเปล่า
  `ui/main.gd` จึงยืมฟอนต์ไทยจากระบบผ่าน `SystemFont` — **ตอนจะปล่อยจริงต้องฝังฟอนต์ที่มีสิทธิ์ใช้งาน**
  ลงในโปรเจกต์ ไม่งั้นเครื่องที่ไม่มีฟอนต์ไทยจะอ่านไม่ออก

### ที่ของจริงต่างจาก ART-DIRECTION / CLAUDE-CODE-BRIEF — อย่าแก้กลับ

- **`icon_bake` รัน headless ไม่ได้** โหมด headless ของ Godot ใช้ตัวเรนเดอร์หลอก
  `viewport.get_texture().get_image()` คืน `null` ต้องรันแบบเปิดหน้าต่าง (สคริปต์ปิดตัวเองให้)
- **API ของแท่นโชว์ชื่อ `show_item()` ไม่ใช่ `show()`** เพราะ `Control` มี `show()` ของตัวเองอยู่แล้ว
  ทับแล้ว GDScript จะ parse ไม่ผ่านทั้งไฟล์
- **id ของพาหนะคือ `public · moto · usedcar · newcar · luxury`** ตาม `data/places.json`
  (ART-DIRECTION ข้อ 3 เขียน `bus/motorbike/car_used/...` ไว้ผิด) — กฎ "ชื่อไฟล์ = id ใน data" ชนะเสมอ
- **ดีลไม่มี id คงที่** (`id` เป็นเลขรันไทม์) โมเดลและไอคอนของดีลจึงอ้างด้วย *ประเภท* แทน
  → `world/models/assets/<kind>.glb` เช่น `micro.glb`, `realestate.glb`
- **`SubViewport` ทุกตัวต้องตั้ง `own_world_3d = true`** ค่าเริ่มต้นคือใช้โลก 3D ร่วมกับพ่อ
  ถ้าลืม ฉากเมืองกับแท่นโชว์จะไปกองในโลกใบเดียวกัน แล้วถนนกับตึกจะโผล่หลังของบนแท่นโชว์
  (`world_check` ตรวจข้อนี้ให้แล้ว)
- **ฉากเมืองห้ามกว้างเต็มจอ** — กล้อง orthographic size 22 ล็อกความสูงไว้ที่ 22 หน่วย
  ความกว้างที่เห็นจึงผันตามอัตราส่วนภาพล้วนๆ · เต็มจอ 16:9 = เห็นกว้างราว 140 หน่วย
  ขณะที่ถนนทั้งเส้นยาวแค่ 50 เมืองจะลอยอยู่กลางพื้นว่าง — `ui/main.gd` จึงบีบแถบฉาก
  ไว้ที่ 1000×300 (ราว 3:1) ด้วย `CenterContainer`
- **`arrive` ถูกยุบทิ้ง** — เสียง "เดินถึงที่หมาย" ดังบ้างไม่ดังบ้างเพราะแอนิเมชันเดินข้ามได้
  (กฎ `world/` ข้อ 4) ผู้เล่นจะไม่มีทางรู้ว่าทำไมบางครั้งเงียบ · การเดินทางมีเสียงเดียวคือ `travel`
  ตอนกดปุ่ม ซึ่งเป็นจังหวะที่ core เปลี่ยนสถานะจริง
- **บัส `SFX` สร้างจากโค้ดใน `WQAudio._ensure_bus()`** ไม่ได้ใช้ `default_bus_layout.tres`
  เพราะ `--headless` เริ่มมาด้วย `bus_count = 1` การสร้างเองทำให้ทุกโหมดเหมือนกันและเทสต์ได้
- **`AudioStreamWAV.save_to_wav()` ไม่มีช่องใส่ metadata** ต่างจาก glTF ที่มี `copyright`
  ตราประทับ "อบจากโค้ด" จึงอยู่ใน `audio/sfx/baked.json` เป็น sha256 ต่อไฟล์แทน
- **จุดลูปของเพลงตั้งจากโค้ดตอนโหลด ไม่ใช่ติดมากับไฟล์** — Godot นำเข้าไฟล์เสียงแล้วไม่ลูปให้
  (ตรวจแล้วกับ `.wav`: `loop_mode = 0`) ต้อง `duplicate()` แล้วตั้งลูปเอง — `.wav` ใช้ `loop_mode`
  กับ `loop_begin`/`loop_end` ส่วน `.ogg`/`.mp3` ใช้พร็อพเพอร์ตี้ `loop` (duplicate ก่อนเสมอ
  ไม่งั้นไปแก้ตัวที่ทั้งโปรเจกต์แคชร่วมกัน)
